# HD农场 — بوت مبيعات ذكي لمزارع Hay Day

بوت تيليجرام يتحدث مع العملاء بلغتهم (العربية بكل لهجاتها، الإنجليزية، وأي لغة) باستخدام Claude من Anthropic،
ويبيع مزارع Hay Day من مخزون حقيقي، مع لوحة تحكم ويب مستقلة ومحمية.

## كيف يعمل

- **الذكاء الاصطناعي يتكلم فقط.** كل معلومة عن المزارع والأسعار والطلبات يأخذها من أدوات تقرأ قاعدة البيانات
  (`app/services/ai.py`). لا يستطيع تغيير سعر أو حجز أو تأكيد دفع أو تسليم.
- **النظام ينفّذ:** عندما يحدد العميل ما يريد، يجهّز النظام ملخصاً رسمياً بالسعر النهائي وزر تأكيد.
  عند التأكيد تُحجز المزارع مؤقتاً (`reservation_minutes`) بقفل ذري (`FOR UPDATE SKIP LOCKED`) فلا تُباع مرتين.
- **الدفع لكل طلب:** يختار العميل وسيلة الدفع، يرسل صورة الإثبات ثم رقم العملية. لا يتأكد الدفع إلا بموافقة
  مشرف (من اللوحة أو من إشعار تيليجرام). بعد الموافقة فقط تُفك تشفير Token ID وكلمة المرور وتُرسل للعميل.
- **التحويل للإدارة:** عند عدم التأكد، أو طلب العميل لشخص، أو تعطل الذكاء الاصطناعي، تُحوَّل المحادثة للإدارة
  ويتوقف الرد الآلي لذلك العميل حتى تعيد تفعيله.
- **لا ضياع عند إعادة التشغيل:** كل الحالات في PostgreSQL؛ مهمة دورية كل 30 ثانية تنهي الحجوزات المنتهية
  وتعيد محاولة التسليمات التي انقطعت.

حالات الطلب: بانتظار تأكيد الطلب ← بانتظار الدفع ← إثبات الدفع مستلم ← الدفع قيد المراجعة ← الدفع مؤكد ←
الطلب قيد التنفيذ ← تم التسليم (أو: ملغي / مرفوض مع السبب).

## البنية

```
app/
  main.py            تشغيل البوت + اللوحة + المهام الدورية
  config.py          الإعدادات من متغيرات البيئة
  security.py        تشفير Fernet + بصمة HMAC لمنع تكرار Token ID + كلمات مرور المشرفين
  services/          منطق العمل: farms, orders, payments, customers, ai, stats, admins, system, backup
  bot/               واجهة تيليجرام: handlers (العملاء)، admin_tg (مراجعة الدفع من تيليجرام)، messenger، texts
  api/               FastAPI: تسجيل الدخول (JWT + CSRF + رمز تيليجرام) وكل عمليات اللوحة
  web/               لوحة التحكم (HTML/JS/CSS بدون مكتبات خارجية)
migrations/001_schema.sql   مخطط قاعدة البيانات
scripts/             gen_keys, create_admin, backup.sh, restore.sh
tests/               اختبارات على PostgreSQL حقيقي مع نموذج ذكاء اصطناعي وهمي
docs/ADMIN_GUIDE.md  دليل المشرف
```

## التشغيل محلياً

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # املأ القيم
python -m scripts.gen_keys      # يولّد ENCRYPTION_KEY و JWT_SECRET
set -a; . ./.env; set +a
python -m app
```

اللوحة على `http://localhost:8080<ADMIN_PANEL_PATH>`.

## النشر على Railway

1. أنشئ مشروعاً وأضف خدمة PostgreSQL **مستقلة** لهذا البوت.
2. أضف خدمة من هذا المستودع (يُبنى من `Dockerfile`).
3. اضبط المتغيرات من `.env.example`، ومنها `DATABASE_URL=${{Postgres.DATABASE_URL}}` و `ANTHROPIC_API_KEY`.
4. ولّد دومين للخدمة وضعه في `PUBLIC_URL`.
5. أضف Volume على `/srv/backups` إن أردت حفظ النسخ الاحتياطية على القرص (وهي تُرسل للمالك على تيليجرام أيضاً).

خدمة واحدة فقط (`numReplicas: 1`) لأن البوت يعمل بنظام polling.

## الأسرار

كل الأسرار في متغيرات البيئة فقط. احتفظ بنسخة من `ENCRYPTION_KEY` خارج الخادم: بدونه لا يمكن فك Token ID
وكلمات المرور حتى من نسخة احتياطية.

## النسخ الاحتياطي والاستعادة

- تلقائي كل `BACKUP_EVERY_HOURS` ساعة، ويُرسل للمالك على تيليجرام. يدوي من اللوحة (النسخ الاحتياطي).
- الاستعادة: أوقف الخدمة ثم
  `DATABASE_URL=... ./scripts/restore.sh backups/hdfarm-YYYYMMDD-HHMMSS.dump` ثم شغّلها بنفس `ENCRYPTION_KEY`.
