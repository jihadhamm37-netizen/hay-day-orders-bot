# متجر مزارع Hay Day — بوت تيليجرام + لوحة تحكم ويب

نظام كامل لبيع مزارع Hay Day بعملة USDT: بوت تيليجرام للزبائن، لوحة تحكم ويب مستقلة للإدارة،
وقائمة إدارة داخل البوت — والجميع متصل بقاعدة PostgreSQL واحدة.

```
 الزبون ──► بوت تيليجرام (aiogram) ─┐
                                   ├──► طبقة الخدمات (app/services) ──► PostgreSQL
 المشرف ──► لوحة الويب ──► Backend API (FastAPI) ─┘        ▲
 المشرف ──► قائمة الإدارة داخل البوت ──────────────────────┘
```

البوت واللوحة يستخدمان **نفس طبقة الخدمات ونفس قاعدة البيانات**، لذلك أي تغيير في السعر أو المخزون
أو الرصيد يظهر فوراً في الطرفين. اللوحة لا تتصل بالقاعدة مباشرة، بل عبر API محمي بتسجيل دخول وصلاحيات.

## 1) ما الذي يعمل فعلياً

### للزبون (داخل البوت)
| الزر | الوظيفة |
|---|---|
| 🛒 شراء المزارع | قائمة الأنواع (LVL • Barn/Silo • السعر • المتوفر) + تصفية مثل `lvl>=70 price<=12` ← تفاصيل النوع ← تأكيد ← تسليم فوري |
| 💼 محفظتي | الرصيد وسجل كل الحركات برقم عملية فريد وتاريخ ووقت |
| 💳 شحن الرصيد | اختيار المبلغ ← عرض معرّف Binance Pay **1127859028** مع زر نسخ ← لقطة الإثبات ← رقم Order ID ← مراجعة |
| 📦 طلباتي | الطلبات وحالاتها، إعادة عرض بيانات الدخول للطلبات المكتملة، إعادة الإرسال إذا فشل التسليم |
| 🛟 الدعم الفني | رسالة الدعم + زر مراسلة حساب الدعم |

رسالة التسليم تحتوي أزرار: **📋 نسخ ID**، **📋 نسخ Password**، **📋 نسخ البيانات كاملة**.

### للإدارة
- **لوحة ويب** (رابط سري + كلمة مرور + رمز تحقق يُرسل عبر البوت): إحصائيات ومخطط 30 يوماً، الأنواع والمخزون،
  استيراد CSV/لصق نصي مع فحص مسبق، تعديل الأسعار (للنوع أو سعر خاص لحساب)، إيقاف نوع/حساب، الطلبات والتسليم والاسترداد،
  مراجعة الشحن مع صورة الإثبات، المستخدمون والأرصدة وتعديلها مع السبب، الحركات المالية ومطابقة الأرصدة،
  الإعدادات ورسائل البوت، المشرفون والصلاحيات، سجل العمليات، التنبيهات، النسخ الاحتياطي. متجاوبة مع الهاتف.
- **قائمة 🛠 لوحة الإدارة داخل البوت** (تظهر فقط لمعرّفات تيليجرام المصرح لها): إضافة نوع، إضافة حسابات فردية/جماعية/CSV،
  تعديل الأنواع والأسعار والسعات، عرض المخزون، الإيقاف، قبول/رفض الشحن (مع أسباب جاهزة أو مكتوبة، أو قبول بمبلغ مختلف)،
  الطلبات، البحث عن مستخدم بـ Telegram ID، إضافة/خصم رصيد مع السبب، الإعدادات، سجل النشاط، نسخة احتياطية.

### الإشعارات
- للمدير: طلب شحن جديد (مع الصورة وأزرار قبول/رفض)، كل عملية بيع، نفاد/انخفاض المخزون، فشل تسليم، فشل نسخ احتياطي.
- للزبون: قبول/رفض الشحن مع السبب، نجاح الشراء والتسليم، تعديل الرصيد من الإدارة، الاسترداد.

### الحالات
- الشحن: بانتظار الدفع، قيد المراجعة، مقبول، مرفوض، ملغي.
- الطلب: بانتظار التأكيد، قيد المعالجة، مكتمل، ملغي، يحتاج إلى مراجعة.

## 2) كيف تُمنع الأخطاء المالية والبيع المكرر

| الخطر | الحماية |
|---|---|
| بيع الحساب نفسه مرتين | قفل الصف `FOR UPDATE SKIP LOCKED` + فهرس فريد يمنع ربط الحساب بأكثر من طلب حي (`orders_account_once`) |
| ضغط زر الشراء عدة مرات | انتقال الطلب من «بانتظار التأكيد» إلى «قيد المعالجة» يتم مرة واحدة فقط ذرياً، ومفتاح فريد `order:{id}` للخصم |
| الخصم بدون تسليم | الحجز + الخصم + ربط الطلب في معاملة واحدة؛ لا يُعتبر الطلب مكتملاً إلا بعد قبول تيليجرام لرسالة البيانات. إذا فشل الإرسال يصبح «يحتاج إلى مراجعة» ويُنبَّه المدير (إعادة إرسال / تأكيد يدوي / استرداد) |
| توقف الخادم أثناء التسليم | مهمة دورية تحوّل الطلبات العالقة إلى «يحتاج إلى مراجعة» وتنبّه المدير |
| اعتماد الشحن مرتين | انتقال «قيد المراجعة ← مقبول» ذري + مفتاح فريد `deposit:{id}` (اختُبر مع 6 ضغطات متزامنة) |
| إثبات دفع واحد لأكثر من طلب | فهارس فريدة على معرف صورة تيليجرام وعلى Order ID (بدون حساسية لحالة الأحرف) |
| رصيد سالب | قيد `CHECK (balance >= 0)` + فحص داخل الـ trigger |
| تعديل الرصيد بدون سجل | **قاعدة البيانات نفسها ترفض** أي `UPDATE` مباشر على الرصيد؛ الطريقة الوحيدة هي إدراج حركة في `wallet_transactions` |
| تعديل/حذف السجل المالي | `wallet_transactions` و `audit_log` للإضافة فقط (trigger يمنع التعديل والحذف) |
| حذف حساب مباع | trigger يمنع الحذف + لقطة من بيانات النوع محفوظة في كل طلب |

بيانات الدخول (ID وPassword) **مشفّرة** في القاعدة (Fernet: AES + HMAC) بمفتاح `ENCRYPTION_KEY`.
اللوحة لا تعرضها أبداً (تُظهر ID مخفياً مثل `hd7•••9`)، ولا تظهر إلا للمشتري صاحب الطلب المكتمل.

## 3) التشغيل على Railway (الموصى به)

1. ارفع المجلد إلى مستودع GitHub خاص.
2. في Railway: **New Project ← Deploy from GitHub repo** واختر المستودع (يستخدم `Dockerfile` و`railway.json` تلقائياً).
3. أضف قاعدة بيانات: **New ← Database ← PostgreSQL**.
4. في خدمة البوت ← **Variables** أضف (انظر `.env.example`):
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `BOT_TOKEN` من @BotFather
   - `ENCRYPTION_KEY` و `JWT_SECRET` و `ADMIN_PANEL_PATH` — أنشئها محلياً بـ `python -m scripts.gen_keys`
   - `OWNER_TELEGRAM_IDS` = رقمك في تيليجرام (من @userinfobot)
   - `INITIAL_ADMIN_USERNAME` و `INITIAL_ADMIN_PASSWORD` (10 أحرف+، حروف كبيرة وصغيرة ورقم)
5. **Settings ← Networking ← Generate Domain**، ثم ضع الرابط في `PUBLIC_URL`.
6. أضف **Volume** على المسار `/srv/backups` إذا أردت حفظ النسخ الاحتياطية على الخادم (النسخ تُرسل لك على تيليجرام في كل الأحوال).
7. بعد النشر: افتح البوت وأرسل `/start` (مهم: ليتمكن البوت من مراسلتك برمز الدخول)، ثم افتح
   `https://your-app.up.railway.app/<ADMIN_PANEL_PATH>`.

> شغّل **نسخة واحدة فقط** من الخدمة (البوت يعمل بنظام polling). إذا أردت فصل البوت عن اللوحة:
> خدمتان من نفس المستودع، الأولى `MODE=bot` والثانية `MODE=api`، بنفس المتغيرات.

**التكلفة:** الكود مُسلَّم كاملاً هنا. التكلفة الوحيدة هي الاستضافة — على Railway عادةً حوالي 5 دولارات شهرياً
للبوت + قاعدة البيانات بحجم استخدام متجر صغير (تحقق من صفحة الأسعار الحالية لديهم).

## 4) التشغيل محلياً أو على VPS

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # واملأ القيم
python -m scripts.gen_keys      # والصق الناتج في .env
set -a && . ./.env && set +a
python -m app                   # ينشئ الجداول تلقائياً ثم يشغّل البوت واللوحة
```
على VPS استخدم `systemd` أو `docker build -t hayday . && docker run --env-file .env -p 8080:8080 hayday`
خلف Nginx/Caddy مع HTTPS (الكوكيز تتطلب HTTPS عند `COOKIE_SECURE=true`).

الجداول تُنشأ عبر الترحيلات في `migrations/` تلقائياً عند كل تشغيل (يُطبَّق الجديد فقط).

## 5) إدارة المشرفين

- **في البوت:** كل رقم في `OWNER_TELEGRAM_IDS` مالك كامل الصلاحيات. والمشرفون المضافون من اللوحة مع `Telegram ID`
  يحصلون على قائمة الإدارة بحسب دورهم. التحقق دائماً **بالرقم** وليس باسم المستخدم.
- **في اللوحة (المالك):** صفحة «المشرفون» ← مشرف جديد: اسم مستخدم، كلمة مرور، Telegram ID، والدور:
  - **المالك:** كل شيء بما فيه المشرفون والنسخ الاحتياطي.
  - **مشرف:** المخزون، الطلبات، الشحن، الأرصدة، الإعدادات.
  - **دعم فني:** العرض ومراجعة الشحن والطلبات فقط (لا تعديل أرصدة ولا مخزون).
- عند ربط Telegram ID بحساب اللوحة يصبح الدخول بخطوتين: كلمة المرور + رمز من 6 أرقام يصلك من البوت.
- قفل تلقائي 15 دقيقة بعد 5 محاولات فاشلة، وأي تعديل على المشرف يُنهي جلساته.
- نسيت كلمة المرور؟ من الخادم: `python -m scripts.create_admin USERNAME --reset-password`.

## 6) تغيير بيانات الدفع والرسائل

اللوحة ← **الإعدادات والرسائل** (أو في البوت: 🛠 ← ⚙️ الإعدادات): معرّف Binance Pay، تعليمات الدفع،
أقل/أعلى مبلغ شحن، طلب Order ID، رسالة الترحيب، رسالة الدعم وحساب الدعم، إخفاء الأنواع النافدة،
حد تنبيه انخفاض المخزون. التغيير يُطبق فوراً ويُسجَّل في سجل العمليات (القيمة القديمة والجديدة).

### التحقق الآلي من Binance Pay (اختياري)
1. في Binance: **API Management** ← أنشئ مفتاحاً **بصلاحية القراءة فقط** (لا تفعّل التداول أو السحب)، ويُفضّل تقييده بعنوان IP.
2. ضع `BINANCE_API_KEY` و `BINANCE_API_SECRET` في المتغيرات وفعّل «التحقق الآلي» من الإعدادات.
3. عند إرسال الزبون Order ID يبحث النظام في سجل Binance Pay (`/sapi/v1/pay/transactions`) عن عملية **واردة**
   بنفس الرقم وبعملة USDT وبنفس المبلغ تماماً وبعد وقت إنشاء الطلب — فإن طابقت يُقبل الشحن تلقائياً،
   وإلا يبقى للمراجعة اليدوية مع ملاحظة السبب. **اختبر هذه الميزة بتحويل صغير قبل الاعتماد عليها.**

## 7) صيغة استيراد الحسابات (CSV)

```csv
id,password,price,note
farmer001,Pass#1,,
farmer002,Pass#2,12.5,مزرعة مميزة
```
- عمود `price` اختياري (سعر خاص لهذا الحساب؛ الفارغ = سعر النوع)، و`note` اختياري. صف العناوين اختياري.
- يقبل الفاصلة `,` أو `;` أو Tab. يُفحص التكرار داخل الملف ومع المخزون الحالي والقيم الفارغة والأسعار غير الصالحة
  **قبل** الحفظ، وتظهر لك النتيجة لتؤكد. في البوت: أرسل الملف أو الصق أسطراً بصيغة `ID:Password`.
- عند وجود أسعار خاصة يعرض البوت للزبون زر شراء لكل سعر مع عدد المتوفر منه.

## 8) النسخ الاحتياطي والاستعادة

- **تلقائي:** كل `BACKUP_EVERY_HOURS` ساعة (افتراضياً 24) بصيغة `pg_dump` المضغوطة، ويُرسل الملف لكل مالك عبر تيليجرام،
  ويُحتفظ بآخر 14 نسخة في `BACKUP_DIR`.
- **يدوي:** من اللوحة (النسخ الاحتياطي ← نسخة الآن ← تنزيل) أو البوت (🗄) أو `./scripts/backup.sh`.
- **الاستعادة:**
  ```bash
  # أوقف البوت أولاً
  DATABASE_URL=postgresql://... ./scripts/restore.sh hayday-20261013-000000.dump
  # ثم شغّله بنفس ENCRYPTION_KEY
  ```
- ⚠️ احفظ `ENCRYPTION_KEY` في مكان آمن منفصل عن النسخ (مدير كلمات مرور مثلاً). النسخة بدون المفتاح لا تكشف
  كلمات المرور، وبدون المفتاح لا يمكن استرجاعها.
- Railway يوفر أيضاً نسخاً احتياطية لقاعدة PostgreSQL من إعدادات الـ Volume.

## 9) الاختبارات

```bash
pip install -r requirements-dev.txt
export TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/hayday_test   # قاعدة فارغة مخصصة للاختبار
pytest -q
```
38 اختباراً على PostgreSQL حقيقي، منها:
- 30 مشترياً متزامناً على 5 حسابات ← تُباع 5 فقط، كل حساب لمشترٍ واحد، والبقية لا يُخصم منهم شيء.
- 8 ضغطات متزامنة على «تأكيد الشراء» ← خصم واحد وتسليم واحد.
- 6 موافقات متزامنة على طلب شحن ← إضافة رصيد مرة واحدة.
- إعادة استخدام صورة أو Order ID ← مرفوضة.
- فشل التسليم (المستخدم حظر البوت) ← «يحتاج إلى مراجعة» + تنبيه + إعادة الإرسال تعمل.
- الاسترداد مرة واحدة حتى مع ضغطتين متزامنتين، ومطابقة كل الأرصدة مع السجل.
- قاعدة البيانات ترفض تعديل الرصيد المباشر وحذف/تعديل السجل المالي وحذف الحساب المباع.
- اللوحة: الدخول، القفل بعد المحاولات، رمز تيليجرام، حماية CSRF، صلاحيات الأدوار، عدم تسرب كلمات المرور في أي استجابة.
- البوت: مسارات كاملة عبر aiogram (الشراء وأزرار النسخ، الشحن وقبول المدير من تيليجرام، إضافة نوع وحسابات من البوت).

## 10) ملاحظات تشغيلية

- الخطوات المفتوحة في البوت (مثل انتظار صورة الإثبات) تُحفظ في الذاكرة؛ عند إعادة تشغيل الخادم يكفي أن يضغط الزبون
  الزر من جديد — لا يضيع أي مال أو طلب لأن كل ما هو مهم محفوظ في القاعدة.
- رسالة الإدارة التي تحتوي كلمات مرور ملصوقة تُحذف تلقائياً من محادثة البوت بعد قراءتها.
- طلب الشراء غير المؤكد ينتهي بعد 15 دقيقة، وطلب الشحن غير المدفوع بعد 24 ساعة.
- رابط اللوحة السري + `noindex` + عدم وجود أي إشارة لها في الصفحة الرئيسية `/`.

## هيكل المشروع

```
app/
  main.py            نقطة التشغيل (البوت + API + المهام الدورية)
  config.py          الإعدادات من متغيرات البيئة
  db.py              الاتصال وتشغيل الترحيلات
  security.py        التشفير وكلمات مرور المشرفين والأرقام المرجعية
  services/          منطق العمل المشترك: wallet, catalog, orders, deposits, binance, admins, stats, system, backup
  bot/               customer.py (الزبون) · admin.py (الإدارة في تيليجرام) · messenger.py · ui.py
  api/               server.py (الـ API) · auth.py (الجلسات، CSRF، الصلاحيات)
  web/               لوحة التحكم (HTML/CSS/JS بدون مكتبات خارجية)
migrations/001_init.sql   مخطط الجداول والقيود والـ triggers
scripts/                  gen_keys · create_admin · backup.sh · restore.sh
tests/                    اختبارات المتجر واللوحة والبوت
```
